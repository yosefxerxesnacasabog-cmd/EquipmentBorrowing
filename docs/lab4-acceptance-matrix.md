# Lab 4 acceptance and traceability matrix

Use the [use-case suite](lab4-use-case-suite.md) for the full scenarios and business rules. The outcome column records the checks that were actually observed. Use a disposable database for further validation, especially tests that deliberately cause failures.

| Acceptance / use case | Implementation and expected outcome | Observed evidence |
| --- | --- | --- |
| A01 / UC-01 | **Equipment > All equipment** displays identifier, name, description and availability. | The desktop catalog showed the seeded equipment, then the renamed test item after restart. [Integration](lab4-integration-verification.md) |
| A02 / UC-02 | **Equipment > Available only** shows available items. | A checkout made the item disappear from the available results. [Checkout and return](lab4-catalog-checkout-verification.md) |
| A03 / UC-03 | **Borrow Equipment** with one item creates an active loan and marks the item unavailable. Invalid requests leave both unchanged. | Single checkout and fresh database readback passed. An ineligible student, missing equipment and an invalid date were rejected. [Checkout and return](lab4-catalog-checkout-verification.md) |
| A04 / UC-04 | **Borrowings** shows active loans with related students, items and dates. | Active loans appeared with the expected details, including after restart. [Integration](lab4-integration-verification.md) |
| A05 / UC-05 | **Confirm return of selected borrowing** retains the row, records the actual date and makes the item available. | Fresh readback found the same returned row and the item available. A repeat return was rejected. [Checkout and return](lab4-catalog-checkout-verification.md) |
| A06 / UC-06 | **Check out multiple items** validates distinct items and the active-loan limit at the transaction boundary. | Two active rows persisted after restart. A one-item request was rejected. A forced failure after the first insert rolled back both loan and availability changes. [Multi-item checkout](lab4-multi-checkout-verification.md) |
| A07 / UC-07 | **History & Search > Student history** loads the selected student's active and returned rows and associated equipment asynchronously. | Desktop results showed both statuses. | A08 / UC-08 | **History & Search > Equipment history** loads the selected item's active and returned rows and associated students asynchronously. | The laptop showed both statuses and the tablet showed an empty history. | A09 / UC-09 | **History & Search > All borrowings** combines case-insensitive partial search, status and date ordering. **Clear filters** resets the criteria. | Desktop partial search returned the expected projector. A service check confirmed an item with an active loan kept its relationship and unavailable status. [Equipment verification](lab4-equipment-verification.md) |
| A17 | Apply the PostgreSQL migration and check persisted data and schema constraints with a separate connection. | The migration applied to an empty database. [Migration](lab4-postgresql-verification.md), [Integration](lab4-integration-verification.md) |

[Integration](lab4-integration-verification.md) |
